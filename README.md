# 几何读图任务中的 SFT 与 RL：个人实验记录

> 更新至 2026-10-15。模型：Qwen2.5-VL-3B-Instruct。主线：SFT 冷启动 → 可验证反馈 → RL。
>
> 当前结果：E09 将混合开发集的严格终值命中从 43/161 提高到 65/161。后续两组连续 RL 均完成 64 次更新；同 FP32 配置下，直接组直接作答 64→67/161，工具组允许工具作答 20→25/161。涨分包含格式改善和错误推导的末值命中，尚未证明稳定的推理能力提升，也未观察到开发集上的工具闭环收益。

这是我的个人学习与实验记录，记录数据准备、失败尝试、训练结果和对结果的理解。它不是一个已经取得稳定提升的完整方法，也不是可直接运行的训练框架。

## 为什么做这个实验

之前的任务偏重格式和信息提取。我希望进一步研究：面对需要读图、识别几何关系、列式与计算的任务，SFT 能否建立基础能力，再通过 RL 改进解题策略。

最初我在少量样本上反复调整，围绕四道题改写解答、增加几何事实监督，随后扩大到六类各 30 道题，共 180 道。结果没有稳定提高。这段过程暴露的问题是：我经常根据局部错误调整数据，但没有始终明确每轮实验的假设，也没有充分区分数据质量、数据分布、训练预算和评分格式的影响。

因此，后续先固定数据划分、审核解答，再分别观察 SFT、工具交互和 RL 的作用。这里以几何任务为起点，实际使用的是三个来源的混合数据，不是仅使用 Geometry3K。

## 数据：从 2,000 道候选到 953 道训练题

最初按 Geo170K / Geometry3K / MathV360K = 1,000 / 600 / 400 准备了 2,000 道训练候选，另外保留 200 道开发候选。经过图文审核、解答修订、关联题隔离和训练侧去重，最终形成 953 道 SFT 训练题。

| 数据来源 | SFT 训练题 | 可评分开发题 |
|---|---:|---:|
| Geometry3K | 489 | 88 |
| Geo170K | 121 | 54 |
| MathV360K | 343 | 19 |
| **合计** | **953** | **161** |

MathV360K 的 343 道训练题包括 UniGeo 269 道、GEOS 30 道、TabMWP 44 道。因此，训练集还包含表格文字题，不能把所有样本都视为几何读图题。

数据审核结合了模型辅助检查和人工反馈，围绕图像、题目条件、所求对象、推导和答案进行修订。1,051 份短解通过本地审核后，75 份因关联开发题或已知保护集图像而隔离，另有 23 份在训练关联组内去重，得到 953 份。开发侧 39 道暂不能可靠评分的题仍保留在开发侧，没有放回训练。

每条 SFT 样本包含：

- 原题图像和问题，选择题保留选项；
- 经核查或修订的简短解答；
- 独立的最终答案行：`Answer: ...`。

审核资料见 [全部2000题_已加审核批注.pdf](docs/全部2000题_已加审核批注.pdf)。这是此前形成的候选审核记录，按原文件收录，没有再次审核或修改 PDF。**2,000 道候选不等于 2,000 道合格训练题，也不等于最终 953 题的训练导出文件。** 后续隔离、去重和修订以本记录说明的最终划分为准。

我学到的是：审核的价值不只是把答案改对，还包括把题目条件、目标对象和推导依据对应起来。例如，写出 `360−70−152` 还不够，需要说明使用的是哪个四边形的内角和，否则示范可能只教会算式，没有教会列式的依据。

## E09：先建立 SFT 冷启动

E09 从原基座开始，在语言部分的 q/v 投影上训练 LoRA，视觉塔和多模态投影器冻结。配置为 rank 8、alpha 16、学习率 `2e-5`、微批 1、梯度累积 4；953 条短解训练 240 步，实际约遍历一轮。120 步用于过程观察，240 步是预先确定的主要比较点。

24 道训练探针来自 953 题内部，包括 Geometry3K 12 道、Geo170K 6 道、MathV360K 6 道。它们观察训练题表现，不是额外的泛化验证集。

| 指标 | 基座 | 第120步 | 第240步 |
|---|---:|---:|---:|
| 开发集严格终值 | 43/161 | 58/161 | **65/161** |
| 训练探针 | 8/24 | 10/24 | **10/24** |

## D12、E10、E11：从可采样到工具监督

D12 从 953 道训练题中固定选出 96 题：Geometry3K 49 道、Geo170K 12 道、MathV360K 35 道。直接和工具分支各题生成 4 条回答，各 384 条，共 768 条；这一步没有参数更新。

| D12 指标 | 直接分支 | 工具分支 |
|---|---:|---:|
| 严格终值命中 | 130/384 | 70/384 |
| 终值未知或无法解析 | 58 | 242 |

这里暴露出的不只是算术问题。加入工具后，模型还需要正确发起调用、等待反馈、读取结果，并按协议结束回答。这些环节都可能失败。

E10 随后使用 80 道不同训练题：64 道工具题与 16 道普通短解题。正常调用示范之外，16 道工具题额外构造了错误后的修复示范，展开成 176 条监督记录：

| 监督目标 | 数量 |
|---|---:|
| 正常工具调用 | 64 |
| 调用后的结束回答 | 64 |
| 修复调用 | 16 |
| 修复后的结束回答 | 16 |
| 普通短解 | 16 |
| **合计** | **176** |

这些示范由人工组织，计算器反馈实际执行生成，不冒充模型自主探索得到的轨迹。

E11 使用相同的 80 题、176 条记录，主要精简并规范结束回复。E10、E11 都从 E09 独立开始，各训练 88 步，固定比较末步结果。

| 指标 | E09 | E10 第88步 | E11 第88步 |
|---|---:|---:|---:|
| 普通开发集 | 65/161 | 55/161 | 56/161 |
| 工具留出题 | 2/24 | 6/24 | 6/24 |
| 工具训练探针 | 3/16 | 2/16 | 4/16 |

这套工具 SFT 配方没有同时保持两种表现。但这还不能证明工具能力与普通解题能力无法兼容，也不能仅凭降分就确定遗忘的机制。数据覆盖、任务分布、监督目标与训练曝光都需要进一步区分。

## E12：扩大普通短解覆盖是否有帮助

两组都从 E09 独立开始，各训练 88 步，实际使用 352 条训练记录。相同的 160 条工具监督各使用一次，另安排 192 次普通短解曝光。

| 组成 | control | replay |
|---|---|---|
| 工具监督 | 相同160条，各1次 | 相同160条，各1次 |
| 普通短解 | 原16题，各重复12次 | 原16题＋新增176题，各1次 |
| 普通题曝光 | 192次 | 192次 |
| 不同训练题总数 | 80题 | 256题 |

| 固定第88步指标 | E09 | control | replay |
|---|---:|---:|---:|
| 开发集 | 65/161 | 52/161 | 57/161 |
| 工具留出 | 2/24 | 7/24 | 7/24 |
| 条件读回 | 2/16 | 5/16 | 4/16 |
| 实际修复且正确结束 | 0/16 | 1/16 | 0/16 |

在这次对照中，扩大普通题覆盖的结果比反复复习少数题好，但没有恢复 E09。普通题的内容和长度也同时改变，不能把差异完全归因于题数，更不能把它当作已经稳定复现的收益。

## 从单步 RL 到连续训练

前几轮实验需要区分“生成了多少轨迹”与“真正做了多少次更新”。一条轨迹是一次完整解题尝试，工具轨迹可以包含多轮模型回复和执行反馈。

| 实验 | 数据与作用 | 实际更新 |
|---|---|---:|
| R04 | 12题×4＝48条，选3个混合组共12条更新 | 1次 |
| R05/R05B | 24题；自然解题96条＋正确反馈条件48条＋错误修复条件48条 | 0次 |
| R05C | 针对2题补充32条修复轨迹 | 0次 |
| R06 | 24题×4＝96条直接回答 | 0次 |
| R07 | 用R06中的4个混合组，共16条、4正12负 | 1次 |

R04 的开发严格终值为 65→62/161，没有达到保留基线的要求。R07 为 64→64/161，权重虽改变，固定评估没有检测到收益。R04 的更新轨迹没有实际工具调用，因此它也不是成功的工具策略训练证据。

中间还遇到数值问题：在参数未更新时，逐token生成与整段前向复算的平均绝对 log 概率差达到 0.05264，超过预设 0.05。固定序列诊断支持这是 BF16 计算路径差异，改为一致的 FP32 路径后，所测差异明显缩小。后续重新生成独立批次，不用新概率替换旧轨迹的分母。

**这也是后续基线从历史 65 变为 64 的原因：数值表示发生变化，必须重新做同配置 before 对照，不能把这 1 分归因于 RL。**

R06 还暴露了奖励的问题：96 条回答中严格末行命中 17 条，但完整过程复核只有 4 条成功，其余 13 条末值命中包含明确推理错误。人工过程检查更严格，却很难支撑持续在线训练；自动答案奖励更容易运行，但可能误奖错误推理。

我需要承认，前期花了很多时间在采样、检查和准入上。它们有工程价值，但少量轨迹加单步更新不足以回答持续 RL 是否有用。R08 因此改为固定预算的连续训练，而不是每次只做一步再判断。

## R08：同一 E09 起点的双组连续 RL

- **直接组：原 E09 → 直接解题 RL。**
- **工具组：同一原 E09＋工具接口 → 工具条件下的 RL。**

工具组没有从 E10/E11/E12 的工具 SFT 模型开始。两组采用相同题目、顺序、种子、奖励和更新预算，各自保持独立的策略与优化器。

既有 953 题已与开发侧隔离；进一步排除工具和诊断评估题族后剩 753 题，再排除 2 道不适合当前标量评分的开放题，得到 751 题候选池，按固定 hash 分层选出 512 题。这里没有重新审核整批数据，也没有依据本轮模型表现选题。

| 来源 | R08 不同训练题数 |
|---|---:|
| Geometry3K | 263 |
| Geo170K | 66 |
| MathV360K | 183 |
| **合计** | **512** |

每轮 8 题，每题 4 条回答，共 32 条新轨迹，聚合做一次参数更新。每组 64 轮、2,048 条轨迹，两组合计 4,096 条；实际各完成 64 次更新。两组共享同一批 512 题，不能计为 1,024 道不同题；也不是把同一批旧回答重复训练 64 次。

本轮使用 GRPO 形式的组内相对优势、裁剪策略目标及固定 E09 参考策略 KL。学习率 `5e-6`、clip `0.2`、KL 系数 `0.02`、梯度范数上限 `1.0`，采用 FP32 未合并 LoRA 路径。每轮由当前策略重新采样，old logprobs 保留实际生成值；模型和优化器一起保存。实际实现与配置的范围见 [结果说明](results/README.md)。

每条轨迹最多生成 512 个模型token。工具组最多2次计算器调用、3轮模型回复，512是全部回复累计预算；宿主反馈只作为后续条件，不计入模型动作损失。相同生成预算不代表相同输入长度或计算耗时。

本轮明确改用**最终答案结果奖励**：完整结束且严格答案正确得1，其余得0。它不认证推理过程，也不因调用工具本身而加分。全同分组优势为0；训练不因某轮低分或混合组不足而停止，但数值和文件错误仍须保留证据处理。

### 固定第64轮结果

两组都在训练前、第32轮和第64轮评估；同一161题分别以直接和允许工具两种协议作答。原有工具与条件诊断也保留，全部评估共2,508次，已经完成。主结果预先固定第64轮，不挑中途最高分。

| RL训练组 | 评估方式 | 训练前 | 第32轮 | 第64轮 |
|---|---|---:|---:|---:|
| 直接组 | 直接作答 | 64/161 | 64/161 | **67/161** |
| 直接组 | 允许工具 | 20/161 | 22/161 | **21/161** |
| 工具组 | 直接作答 | 64/161 | 64/161 | **64/161** |
| 工具组 | 允许工具 | 20/161 | 22/161 | **25/161** |

两组 before 原生输出一致，权重、优化器步数和保留轨迹均经过核验，确认连续训练实际发生。

工具条件在训练前就只有20/161，直接条件是64/161，所以不能写成“RL导致64降到25”。两种条件分别减自己的before；而实际使用结果，工具组25仍低于直接组67。

## 我对这段实验的反思

我之前最主要的问题，不只是样本少或调整次数多，而是没有始终明确：**这一轮验证什么假设，什么结果能支持它，什么结果只能说明局部变化。**

现在我需要分别判断四件事：

1. **训练是否真的发生。** 参数、梯度、概率和恢复是否正确，属于工程问题。
2. **评分为什么提高。** 格式规范、末值命中、正确推理不能混成一个结论。
3. **工具是否贡献收益。** 能发起调用、代码能执行、公式对应题意、最终回答正确，是不同层次。
4. **结果是否稳定。** 少量开发题、单seed和反复使用开发集，都限制了结论范围。

我最初希望用计算器避免低级算错，但现在看到，更前面的瓶颈可能是模型没有正确识别关系、没有列出有效算式，或没有在拿到结果后正确收尾。执行器可以计算表达式，却不会自动修正错误的几何关系。

目前较稳妥的结论是：SFT冷启动改善了混合开发表现，连续RL已经运行并出现小幅严格分数变化，但工具训练的有效正反馈非常稀少，结果奖励也混合了格式与推理因素。下一阶段需要围绕这些可观察的问题提出新的实验假设，而不是只按总分涨跌继续增加样本、步数或更换方向。
